## Findings closed in this pass

1. **CRITICAL — public covariance non-finite input fail-closed contract.**
   `clustered_covariance`, `two_way_clustered_covariance`, `hac_covariance`, and
   `driscoll_kraay_covariance` now reject non-finite `X`/residual arrays before
   signed/grouped reductions. This prevents NaN/Inf score rows from being silently
   converted into zero positive/negative contributions by the magnitude-tiered
   reducer. NumPy, maintained Torch CPU, and physical CuPy/Torch runner coverage
   were added. The internal `ols_covariance` dispatcher was deliberately not
   promoted to the package public API or given a duplicate public-helper scan.

2. **HIGH — projection-created dynamic-range backend coverage.**
   The two-way demeaning path refreshes its stability classification after the
   first entity projection. A dedicated fixture proves the intended transition
   from a safe raw vector to a risky post-projection vector and exercises the
   stable path in maintained Torch CPU plus the physical CuPy/Torch validator.

3. **CRITICAL — order-dependent multi-tier two-way covariance reduction.**
   Maintained Torch 2.0 validation exposed a third-magnitude nonnested two-way
   covariance that passed in isolation but became `Inf` after earlier covariance
   tests. The original multi-tier implementation still reduced signed component
   rows inside BLAS before estimator-level cancellation; an ulp-scale remainder
   could therefore become unrepresentable only after the common physical scale
   was restored.

   The final fix is confined to the path that both has multiple magnitude tiers
   and fails the cross-group row-reduction safety certificate. In that pathological
   branch, grouped row outer products remain separate, float group-debias factors
   are decomposed into exact power-of-two terms, and two compensated error streams
   perform the magnitude-tier / Cameron-Gelbach-Miller inclusion-exclusion / debias
   cancellation before final restoration. Gram-safe multi-tier cases retain the
   vectorized component-matrix path, and ordinary single-tier covariance remains
   unchanged.

   The maintained Torch 2.0 Stage-B covariance file passed twice consecutively
   before the production fix was committed. The same gate then passed the broader
   Stage-C covariance, Torch CPU, and physical-runner contract suites, `compileall`,
   and `git diff --check`.

4. **MEDIUM — precision fallback scope/performance.**
   An initial correct-but-overbroad row-level implementation would have sent every
   locally multi-tier two-way case through Python row expansion. The final code
   evaluates `_component_row_reduction_needs_expansion` first: only unsafe
   cross-group reductions use the row-level compensated fallback; Gram-safe
   multi-tier cases continue to use vectorized BLAS/GPU component products.

5. **MEDIUM — stale physical-artifact documentation.**
   EN/CN covariance documentation identifies the existing P100 artifacts as
   historical reference evidence rather than current-head physical acceptance.
