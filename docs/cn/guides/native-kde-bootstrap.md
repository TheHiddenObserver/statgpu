# 原生 KDE bootstrap

> 语言：中文  
> 最后更新：2026-10-22  
> 切换：[English](../../en/guides/native-kde-bootstrap.md)

使用 `kde_bootstrap_confidence_interval` 或
`kde_confidence_interval(method="bootstrap")` 可计算平滑密度的逐点百分位区间。
CuPy 和 Torch 在所选设备上完成随机抽样、重采样、带宽选择、重拟合、密度及分位数
计算。Torch CPU 也受支持；仅选择 Torch 库不代表使用了 CUDA。
参数和形状见 [API 参考](../reference/survival-smoothing-api.md)。

## 输入与统计含义

原生路径支持数值带宽因子，以及 `scott`、`silverman`、`nrd`、`nrd0`、`ucv`、
`bcv`、`sj`、`sj-ste`、`sj-dpi`。Gaussian、rectangular、triangular、
Epanechnikov、biweight 和 triweight 核支持已有的多元输入形状；cosine 与
optcosine 仍仅支持一维。可转换的实数输入，包括 float32 与非连续视图，内部转换
为 float64。有限输入、正权重总和及协方差要求不变。常数或稀疏重采样可能使选择器
失败，此时不会静默换成其他选择器。

按归一化的原始权重有放回地抽取样本行。每次重拟合还会使用被抽中行的原始权重，
并再次归一化。因此权重同时用于抽样和重拟合，不是适用于所有调查权重、频数权重
或重要性权重的通用 bootstrap。请先确认它符合研究设计。
只要剩余权重可以定义有效拟合，就允许零权重。区间是逐点区间，不是同时置信带，
也不校正平滑偏差。

字符串带宽选择器在每次原生重复中重新计算。数值因子保持固定，但每次重复仍重新
估计样本协方差，因此绝对核宽度会变化。NumPy 的一维高斯快速路径则固定最初选出的
因子，即使带宽传入字符串也如此。因此，用字符串选择器比较后端时，统计计算任务
未必相同。需要固定因子的比较时请显式传数值因子；这仍不意味着不同后端产生相同
的随机样本。

加权 R 风格选择器保留分位数重采样扩展，多元 R 风格选择器保留主轴投影扩展。
这些扩展不等价于精确的多元 R 方法。核回归 CV 选择器不是 KDE 的带宽选项。

## 原生 PCA 与加权选择器差异

NumPy 选择器保留历史算法。原生选择器对数值相等的样本使用稳定排序，并将主特征
向量的符号固定为“首个绝对值最大的载荷为正”。计算保持在原生后端，不会为了逐项
复刻历史结果将数组转到 CPU。

这里有两个不同的问题。即使最大特征值唯一、与其他特征值明显分离，一个特征向量
和它的相反数仍代表同一条 PCA 轴。但这里使用的加权线性分位数重采样扩展，对轴的
反向并不保持不变：投影值反向也会改变不等权重的排列顺序，沿累积概率做插值后，
得到的重采样未必只是原结果取反。因此，原生加权多元 UCV/BCV/SJ 系列带宽因子
可能与历史 NumPy 结果有明显差别。这是选择器约定的差异，不只是浮点噪声，也不
局限于重复特征值。

另一个问题是：最大特征值重复时，主方向本身不唯一；最大特征值近似重复时，主方向
对数值扰动敏感。固定向量符号无法消除这种基的歧义，此时包括 nrd 系列在内的投影
选择器也可能随后端或设备而不同。请结合投影诊断信息理解所选方向，不应期待精确
复刻历史 NumPy 因子或跨后端区间逐项相同。需要共同的固定因子计算任务时，可以
显式传数值带宽因子来避开 PCA 带宽选择，但这不会使独立 RNG 的抽样结果相同。

原生多元 PCA 选择在最大特征值重复或数值上近似重复时发出 `RuntimeWarning`，
谱尺度为零也视为歧义情形。判定相对于协方差特征值尺度和 float64 精度进行，
不是使用与数据单位有关的绝对阈值。警告不会切换到 CPU、拒绝拟合或恢复历史因子；
即使没有警告，加权重采样仍可能因符号约定而得到不同结果。

一次成功的公开区间调用会汇总原始拟合与 bootstrap 重拟合的情况，最多发出一次
警告，不会每个重复都提示。`metadata["projection_diagnostics"]` 给出 `status`、歧义投影总数 `count`、
`exact_degeneracy_count`、`near_degeneracy_count`、`zero_scale_count`，以及歧义
投影中的 `min_relative_eigengap`。三个分类计数互斥；没有歧义时计数为零，最小间隔
为 `None`，而不是统计全部 PCA 拟合次数。单独拟合则针对自身的投影发出警告。数值带宽、Scott/Silverman 及
一维选择不使用此 PCA 扩展，因此不产生这种警告。

## 随机状态与可复现性

原生 bootstrap 接受 `numpy.random.default_rng` 支持的输入，包括 `None`、
非负整数种子、`SeedSequence` 与 `Generator`。每次调用从该 NumPy 生成器消耗
四个 uint32 数值，为后端局部生成器设种子。传入 `Generator` 时，它的状态按此
种子桥接操作推进，而不是按原来的主机抽样序列推进。同一生成器的连续调用不会重置
状态；需要重复结果时，应在各次调用中传入相同的整数种子。

实际 bootstrap 索引由后端 RNG 生成，不修改 NumPy、CuPy 或 Torch 的全局随机
状态。可复现性针对固定的后端、软件和设备环境，不保证 NumPy/CuPy/Torch 的
随机序列相同，也不保证复现历史 bootstrap 结果。改变查询分块大小不会改变 RNG
批次。抽样使用 float64 可表示的累积概率，极小的正概率质量可能因舍入而消失。

## 返回边界与内存

`KDEBootstrapResult` 仍面向主机返回：`points`、`estimate`、`lower`、`upper`
及可选的 `bootstrap_samples` 都是 NumPy 数组。最后的传输是明确的返回边界，
不代表原生 bootstrap 内部回退到 CPU。输入转换、标量校验与控制、小规模种子桥接
也可以使用主机。`backend` 字段记录数组库，而不一定代表 GPU 设备；区分 Torch CPU
与 CUDA 时应检查张量所在设备。

`batch_size` 限制查询批大小。可选的正整数 `workspace_bytes` 按估计值约束
bootstrap 管理的缓冲区，并可缩小查询分块。它不会减少观测、查询或重复次数。
如果预算连一个查询及必须保留的缓冲区都容纳不了，会抛出 `MemoryError`。

精确分位数需要保留 `n_resamples * n_query` 的重复值矩阵，即使
`return_bootstrap_samples=False` 也如此。估计还包含分位数副本、单次重拟合缓冲区、
已知选择器缓冲区与查询临时数组，但不包含调用方输入、原始模型、底层库临时空间及
分配器缓存。因此它不是峰值内存或显存硬上限。NumPy bootstrap 与正态区间不应用
这一原生工作区预算。

原生结果的元数据说明执行方式、选择器重拟合、种子桥接、概率精度、主机传输边界、
查询分块和管理内存估计，不是速度或物理 GPU 执行证明。请在目标数据规模上比较
同步后的端到端时间；小规模任务仍可能更适合 NumPy 快速路径。
