# L-BFGS Float32 数值行为

> 语言：中文  
> 最后更新：2026-09-17  
> 页面定位：面向用户的数值精度说明  
> 切换：[English](../../en/guides/lbfgs-float32-precision-contract.md)

## 适用范围

本页说明如何理解 NumPy、CuPy 与 Torch 上原生 float32 L-BFGS 的结果。这里讨论的是有限精度下的数值行为，不改变 L-BFGS 算法、统计目标、解析权重语义、求解器选择或显式 `device` 行为。

算法本身见 [求解器算法](solver-algorithms.md)。

## 为什么不同后端的 float32 系数可能不同

L-BFGS 在有限精度下具有路径依赖。目标函数和梯度归约中的微小舍入差异，可能改变：

- 哪些曲率对进入有限记忆历史；
- Armijo 回溯线搜索执行多少步；
- 后续被接受的迭代点序列；
- 最终是满足梯度停止条件，还是因为进一步的参数变化已经低于 float32 的可分辨尺度而停止。

因此，两次都有效的 float32 求解可能出现“系数差明显大于目标函数值差”的现象。

所以 NumPy float32 得到的系数向量**不应被当作** CuPy 或 Torch float32 结果逐坐标精确一致的基准答案。

## 更合理的比较方式

判断两个 float32 L-BFGS 拟合是否在数值上相符时，应联合查看整个数值状态，而不是只比较最大的系数差：

1. **目标函数值**：不同执行应在适合 float32 的数值尺度上优化同一个声明目标。
2. **驻点程度**：最终梯度或等价停止诊断应表明结果已经接近驻点。
3. **同一后端上的 float64 结果**：需要更严格诊断时，可以把 float32 与同一后端、同一问题的 float64 求解比较。
4. **统计不变量**：例如在归一化权重约定下，把所有正解析权重同时乘上一个常数不应改变统计目标。
5. **请求的执行路径**：显式后端/设备请求应继续在该后端上执行，而不是被静默替换成 CPU 求解。

因此，只要目标函数和驻点诊断在预期的 float32 尺度上相符，单独一个不大的系数差并不足以说明某个后端计算错误。

## 解析权重

对于支持解析 `sample_weight` 的 L-BFGS 路径，归一化带权目标为

$$
L_w(\beta)
=
\frac{\sum_i w_i\,\ell_i(\beta)}{\sum_i w_i}.
$$

把所有正权重同时乘上一个常数不会改变这个目标。有限精度下的优化轨迹仍可能略有差别，但统计目标保持不变。

受支持的惩罚 GLM 路径中解析权重的推断含义见 [惩罚 GLM 推断](penalized-glm-inference.md)。

## 什么时候使用 float64

如果应用要求更严格的跨后端系数可重复性，或者很小的系数差本身就具有实质意义，应使用 float64。

如果目标是保留原生低精度执行，并且 float32 尺度下的目标函数值和驻点精度已经足够，则可以继续使用 float32。调查可疑数值差异时，float64 也是更合适的诊断参考。

## 实际解释方式

如果 NumPy、CuPy 与 Torch 的 float32 L-BFGS 得到略有不同的系数向量：

- 先比较目标函数值；
- 检查收敛情况与驻点诊断；
- 确认各次运行使用相同数据、目标函数归一化、权重、惩罚项与停止控制；
- 需要更严格参考时，把每个后端与其 float64 运行结果比较；
- 如果应用真正要求系数高度一致，而不仅仅是优化到数值等价的目标，应直接使用 float64。

不要为了强迫不同后端的 float32 系数近似逐位一致，而修改统计目标或改变求解器语义。
